# Living Repair Order implementation proof

Evidence class: **hermetic real-component proof**.

Production source under proof: branch `codex/living-repair-order-visual-2026-08-05`
at SHA `4f44c5a828500148367f81d080f0c265d4084e03`, plus the Task 5 proof files
listed below before their proof-only commit.

This receipt preserves the separate pre-code direction receipt at
`docs/proofs/2026-08-05-living-repair-order-visual-proof.md`. It does not
relabel the synthetic design provenance as implementation evidence.

## What is mounted

The local Vite route `/?mode=implementation` renders the real
`TicketDetailScreen`, `InlineQuoteWorkspace`, `ManualQuoteBuilder`, and
`ManualPartSourcing` components. Loopback route fixtures return projections
that must pass the production `parseQuoteBuilderProjection` parser before the
screen receives them.

No lookalike builder is used for this evidence. Next navigation, image, app
header, and ready-to-collect dependencies are narrow test-harness adapters;
quote behavior and visible ticket composition remain the production
components.

## Acceptance evidence

- Assigned technician, advisor, parts, and owner roles each receive one
  job-bound `Build ticket` entry.
- An advisor creates a visible $140.00 part and 1.25 hr × $150.00/hr labor
  line, then observes subtotal $327.50, taxable subtotal $140.00, tax $11.55,
  and total $339.05 before explicitly preparing that exact quote.
- A technician can edit the assigned job while another technician's job stays
  visible and read-only for quote-line and manual-sourcing controls. Existing
  story behavior is outside this slice. The technician never receives
  ticket-wide Prepare.
- Equal-ranked work requires an explicit job choice before `Build ticket`
  appears.
- `Add work` stays collapsed until requested. O'Reilly First Call, PartsTech,
  and RepairLink are passive planned text with no link, button, or outside
  request.
- Prepare collapses the real inline workspace, reprojects `Priced`, exposes
  `Record approval` for the advisor, returns focus to the job, and makes no
  route change.
- Every fixture request is method/path controlled. The tests require zero
  unhandled requests, exactly two line writes, exactly one Prepare write in
  the advisor journey, and zero provider or non-loopback fetches.
- Both viewports pass horizontal-overflow, 44px-target (43.5px sub-pixel
  tolerance), serious/critical Axe, focus, browser fault, and reduced-motion
  assertions.
