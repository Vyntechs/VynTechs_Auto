# Shop OS driver state

- **Outcome:** Make ShopOS's living repair order work flawlessly across every intended role: permitted users can create, find, own, hand off, quote, perform, and close work from the right queue on phone or desktop, without extra pages, reload-feeling transitions, or lost work. The signature is continuity without ceremony: the repair order stays present while only the applicable tool changes.
- **Current slice:** Row 60 is complete, merged, and deployed. A repair order whose every job has reached `done` or `canceled` no longer falls off Today: advisors and owners keep one ticket-level `Ready to collect` card carrying the exact `getTicketRingOut` balance, and selecting it mounts the existing payment/close tool inline on the board. The card leaves only when the server confirms the repair order is no longer open. Row 61 is the next lane: a repair order becomes unfindable the moment it closes, so the counter needs a tenant-scoped lookup that mounts closed work in place.

- **Save a worked job as a canned job (2026-07-28, branch `feat/save-job-as-canned`):** the library used to fill only by hand, so a shop that priced a job perfectly re-priced it from scratch next time. An owner now sees `Save as canned job` on an approved job in the repair-order ledger; one tap files that job's authorized pricing into the library without the repair order moving. The lines come from the immutable approved quote version — the same row `getTicketRingOut` bills from — never the live `job_lines`, which stay editable after approval and would quote the next customer a price the shop never agreed to charge. Domain `4f4e3b9`, surface `23f7454`. Proof: 8/8 new domain tests plus 129/129 across the canned-job and quote neighbours; 93/93 across the five affected surface files; TypeScript clean; the build goes 133 to 134 routes and a stashed-tree diff confirms the single addition is the API route handler, not a page. No migration, no schema change, no production write.
- **Two labor rates, verified not supported (2026-07-28):** the shop bills some customers $155/hr and some $100/hr. A manual labor line is always priced hours × the single `shops.labor_rate_cents`; `buildManualLineInput` at `lib/shop-os/quote-builder-ui.ts:469` ignores the price field entirely whenever a shop rate exists, so the second rate cannot be quoted by hand. Canned jobs are the working path: the Settings editor takes an explicit customer price, hours, and optional labor rate per line, and `applyCannedJobToTicket` copies `priceCents` and `laborRateCents` into the job verbatim rather than recomputing at the shop rate. The durable fix is a per-customer rate that defaults to the shop's — an owner decision plus a migration, not yet taken.

It builds the test database by a *different procedure than production* — which is the exact gap that let the `0045`/`0047` duplicate live undetected. `scripts/db-migrate.mjs` now replays the whole folder from empty in about 1.3s, so the scaffolding is both redundant and the last place where what tests run against diverges from what production is. Replace the whole mechanism with one folder replay.

- **Repo debt closed (PR #203, merged `7fd3885`):** the `0045`/`0047` duplicate `ticket_activity` index creation is fixed with `if not exists`, and `tests/unit/migration-replay.test.ts` now replays all 51 migration files into an empty database on every run — verified to fail with the old `0047` and pass with the new one. Two corrections to what this document previously claimed. First, editing a migration file does **not** re-run it against production: `drizzle-orm/pg-core/dialect.js:62` compares the journal's `when` timestamp against the newest applied `created_at` and never compares the stored hash, so that fix needed no owner gate at all. Second, the app-shell skip link is **not** a defect — measured at all twenty checkpoints it is never focused and sits at `top=-52`; it only appeared in evidence because a full-page screenshot composites `position: fixed` elements at a scroll-dependent offset. Checkpoint screenshots are now viewport captures taken before axe-core enters the document.
- **Migrations, closed (no owner gate needed after all):** the fix was not to resurrect Drizzle's journal but to replace it. `scripts/db-migrate.mjs` applies the folder in filename order and records each file in `public.schema_migrations` with a checksum; `npm run db:migrate` and `db:status` now point at it, and the broken `db:generate` is gone. Re-running migrations was never the right shape — 45 of 51 are not re-runnable, so making them idempotent would have meant rewriting already-applied history. A ledger plus three refusals does it instead: apply to an unrecorded existing database, apply while an applied file changed on disk, and apply while an applied file is missing. Production was baselined through `0048` with a before/after receipt — 63 tables to 64, only `schema_migrations` added, application row counts identical — then health, migration status, and the hosted journey at both widths all passed. Procedure: `docs/operations/2026-07-28-database-migrations.md`.
- **Production schema drift (owner decision, nothing depends on it):** production carries `knowledge_items`, `knowledge_item_vehicles`, and `sessions.cache_hit_platform_id`/`cache_hit_symptom_id` with no source migration. A folder-built database diffed against production is missing **zero** of the columns the application uses, and no TypeScript references any of the four. Dropping them is destructive and unnecessary; recorded rather than acted on.
- **Stop only when:** A review finds a new blocking architecture defect, remote publication/deployment requires authority, production/live-data mutation is required, or a genuine unresolved business decision appears. A verified slice is otherwise a checkpoint, not a handback.
- **Usage balance:** Native tests, type checks, builds, source guards, Git, and the new Golden harness own deterministic proof. Strongest effort stays on role/tenant correctness, transaction boundaries, living-object state reconciliation, and release convergence. The repeated role-flow matrix is now automated rather than founder-tested.
