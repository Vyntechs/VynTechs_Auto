# Shop OS driver state

- **Outcome:** Make ShopOS's living repair order work flawlessly across every intended role: permitted users can create, find, own, hand off, quote, perform, and close work from the right queue on phone or desktop, without extra pages, reload-feeling transitions, or lost work. The signature is continuity without ceremony: the repair order stays present while only the applicable tool changes.
- **Current slice:** Row 60 is complete, merged, and deployed. A repair order whose every job has reached `done` or `canceled` no longer falls off Today: advisors and owners keep one ticket-level `Ready to collect` card carrying the exact `getTicketRingOut` balance, and selecting it mounts the existing payment/close tool inline on the board. The card leaves only when the server confirms the repair order is no longer open. Row 61 is the next lane: a repair order becomes unfindable the moment it closes, so the counter needs a tenant-scoped lookup that mounts closed work in place.
- **Build Quote fix (2026-07-18):** Mobile-only defects on the manual quote builder — inert Add part/labor/fee (editor rendered far below the tap with no scroll/focus), the customer concern overflowing the job card, the sticky Prepare bar occluding the editor, and an unactionable tax-rate warning — were fixed in PR #173 (merged `1a6eaa8`). Proof included 284 files/3,245 tests, TypeScript, production build, and a real-component Chromium render at 390×844 with zero axe violations.
- **Continuity direction (2026-07-20):** Recover the product incrementally from current production `main`; do not merge the stale 48k-line continuity prototype. Preserve transactional and authorization rigor, but remove proof ceremony that adds no user value. Spend boldness on one behavior: a selected repair order quietly reveals the exact next tool and then collapses back into updated proof.

Both are repaired and re-proved.
- **Next safe move:** Start Row 61 — a tenant-scoped, capability-checked, rate-limited repair-order lookup that mounts a closed repair order in place on Today, reusing the shape already proved by `/api/intake/search`.
- **Open gates:** A real shop must choose its diagnostic authorization title, labor hours, and price; code deliberately refuses to invent them. AutoEye, diagnostic-engine execution, and media remain off. Row 60 needed no founder gate; its balance, role, and closure contracts already existed and were reused rather than rebuilt.
- **Worker lanes:** Rows 59 and 60 are closed; Row 61 owns `lib/shop-os/`, `components/screens/today-*`, and the ticket read paths while its lane is open. AutoEYE remains outside ShopOS and diagnostic authorization remains ordinary ShopOS labor, not an engine entrance.
- **Known repo debt (not Row 61 scope):** `0045_shop_os_interruption_ledger.sql` and `0047_shop_os_ticket_activity_fk_indexes.sql` each create `ticket_activity_shop_ticket_job_fk_idx` and `ticket_activity_shop_actor_fk_idx` with no `if not exists`, so a rebuild from an empty database fails at `0047` with `relation already exists` — verified by reading both files. `0045` was amended after production had already applied it, which is why production is healthy and only a fresh build breaks. The fix is not a plain edit: Drizzle tracks a per-migration hash, so changing either file makes it look new to `drizzle-kit migrate` and re-run against production. Treat it as a scoped migration lane with an owner gate, not a drive-by. Separately, the app-shell `Skip to current work` link renders visible over the page whenever an inline workspace boundary takes programmatic focus; it predates Row 60 and appears in the `advisor-quote-draft` checkpoint too.
- **Stop only when:** A review finds a new blocking architecture defect, remote publication/deployment requires authority, production/live-data mutation is required, or a genuine unresolved business decision appears. A verified slice is otherwise a checkpoint, not a handback.
- **Usage balance:** Native tests, type checks, builds, source guards, Git, and the new Golden harness own deterministic proof. Strongest effort stays on role/tenant correctness, transaction boundaries, living-object state reconciliation, and release convergence. The repeated role-flow matrix is now automated rather than founder-tested.
